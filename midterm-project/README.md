# Bank Term Deposit Prediction - ML Zoomcamp Midterm

Binary classification: predict whether a client will subscribe to a term deposit after a
marketing campaign. The deliverable includes the exploratory notebook, a reproducible
training script, a FastAPI prediction service and a Docker image ready for deployment.

## Dataset

- Source: [UCI Machine Learning Repository - Bank Marketing](https://archive.ics.uci.edu/dataset/222/bank+marketing)
- File: `data/bank-full.csv` (45,211 rows, 17 columns, `;`-separated)
- Target: `y` (`yes` / `no`), about 11.7% positive
- Citation: S. Moro, P. Rita and P. Cortez, "A Data-Driven Approach to Predict the Success of
  Bank Telemarketing", Decision Support Systems, 62, 22-31, 2014.
  DOI: 10.1016/j.dss.2014.03.001. Dataset license: CC BY 4.0.

The file is not committed. Download and verify it with:

```bash
python data/download_data.py
```

Expected SHA256:
`d1513ec63b385506f7cfce9f2c5caa9fe99e7ba4e8c3fa264b3aaf0f849ed32d`

## Reproduce

Python 3.12 is recommended.

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
python data/download_data.py
jupyter notebook notebook.ipynb
python train.py
```

`train.py` fits the model on an 80/20 stratified holdout to report honest metrics, then
refits on all rows and writes the deployable artifact.

## Model

XGBoost inside a scikit-learn pipeline (`StandardScaler` for numeric features,
`OneHotEncoder(handle_unknown="ignore")` for categorical features). `duration` is dropped
because it is only known after the call and would leak the target.

| Metric | Value |
| --- | --- |
| 5-fold CV ROC-AUC | 0.7959 +/- 0.0083 |
| Validation ROC-AUC | 0.8088 |
| Test ROC-AUC | 0.8069 |
| Test PR-AUC | 0.4719 |
| Decision threshold | 0.23 (tuned on validation F1) |
| Test precision / recall / F1 at 0.23 | 0.498 / 0.502 / 0.500 |

Hyperparameters: `n_estimators=300`, `learning_rate=0.05`, `max_depth=4`,
`min_child_weight=1`, `subsample=0.9`, `colsample_bytree=0.9`, `tree_method="hist"`.

### Limitations

- Class imbalance: at the default 0.5 threshold recall is only ~0.25. The API uses 0.23 to
  balance precision and recall.
- Temporal drift: training on older rows and testing on the most recent 20% drops ROC-AUC
  to ~0.69, and the positive rate rises from 6.7% to 31.6%. Retraining and monitoring are
  required in production.
- The dataset is from 2008-2010 Portuguese retail banking; results may not transfer.

## Run the API locally

```powershell
.venv\Scripts\activate
uvicorn predict:app --host 127.0.0.1 --port 9696
```

In another terminal:

```powershell
python smoke_test.py
```

```powershell
$body = @{
  age = 41; job = "technician"; marital = "married"; education = "secondary"
  default = "no"; balance = 1200; housing = "yes"; loan = "no"
  contact = "cellular"; day = 15; month = "may"; campaign = 2
  pdays = -1; previous = 0; poutcome = "unknown"
} | ConvertTo-Json

Invoke-RestMethod -Uri http://127.0.0.1:9696/predict -Method Post -Body $body -ContentType "application/json"
```

Example response:

```json
{"subscription_probability": 0.100903, "subscription": false, "threshold": 0.23}
```

`GET /health` returns the model SHA256 and the recorded holdout metrics. `GET /docs` exposes
the interactive OpenAPI documentation.

## Run with Docker

```powershell
docker build -t bank-midterm .
docker run --rm -p 9696:7860 bank-midterm
python smoke_test.py
```

The container listens on port 7860 by default (the Hugging Face Spaces default). Set `PORT`
to override it, for example `docker run -e PORT=10000 -p 9696:10000 bank-midterm`.

## Deployment

### Hugging Face Spaces (requires PRO)

> Hugging Face requires a PRO subscription to host Docker Spaces on free `cpu-basic`.
> Free accounts receive `402 Payment Required`. The steps below apply to PRO accounts.

1. Create a new Space at <https://huggingface.co/new-space>: SDK **Docker**, blank template.
2. Install the CLI and log in with a token that has write access:

   ```powershell
   pip install -U "huggingface_hub[cli]"
   hf auth login
   ```

3. Copy the runtime files into a clean directory and use `space_README.md` as `README.md`
   (the Space needs the YAML front matter with `sdk: docker` and `app_port: 7860`):

   ```powershell
   $space = "C:\temp\bank-space"
   New-Item -ItemType Directory -Force $space | Out-Null
   Copy-Item pipeline.py,predict.py,model.bin,model_metadata.json,requirements.txt,Dockerfile $space
   Copy-Item space_README.md "$space\README.md"
   ```

4. Create the Space and upload the files:

   ```powershell
   hf repos create <username>/<space-name> --type space --sdk docker --public --exist-ok
   hf upload <username>/<space-name> $space --repo-type space
   ```

5. Wait for the build and verify `https://<username>-<space-name>.hf.space/health` and
   `/docs`.

### Render (free)

Render runs the same Dockerfile on its free web-service plan (0.1 CPU, 512 MB RAM, no
credit card). The service sleeps after 15 minutes without traffic and wakes in about a
minute.

1. Push this repository to GitHub.
2. In the Render dashboard choose **New > Web Service** and connect the repository.
3. Set:
   - **Root Directory**: `midterm-project`
   - **Language**: `Docker`
   - **Instance Type**: `Free`
   - **Health Check Path**: `/health`
4. Create the service. Render builds the image and exposes it at
   `https://<service-name>.onrender.com`.
5. Verify `/health` and `/docs`. The first request after a sleep can take about a minute.

The Dockerfile reads `PORT` when present (`${PORT:-7860}`), so the same image works on
Render (which sets `PORT`) and on Hugging Face Spaces (port 7860).
